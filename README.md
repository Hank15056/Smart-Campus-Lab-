# Smart Campus AI

Учебный прототип интеллектуальной веб-платформы для управления инфраструктурой учебного заведения. Это административная панель, где собраны помещения, IoT-датчики, энергопотребление и заявки на ремонт. Модуль AI Analytics находит аномалии и выдаёт рекомендации оператору.

**Автор:** Павлов А.С., группа КС 3-24
**Стек:** HTML5, CSS3, JavaScript (без фреймворков), Chart.js, localStorage, Git + GitHub Pages

## Возможности

| Страница | Что умеет |
|---|---|
| **Login** (`index.html`) | Учебная форма входа с ролями Administrator / Engineer / Operator. Проверяет формат email и длину пароля. |
| **Dashboard** | 6 KPI-карточек и 3 графика Chart.js: энергия по корпусам, статус устройств, тренд температуры и CO₂. Есть уведомления, список проблемных помещений и последние инциденты. |
| **Помещения** | 14 помещений в 4 корпусах. Для каждого показаны температура, CO₂, энергия, занятость и статус Normal / Warning / Critical. Работают поиск и фильтры по корпусу и статусу. |
| **Устройства** | 46 IoT-устройств: датчики температуры и CO₂, счётчики энергии, камеры, контроль доступа. Видно статус online/offline и время последнего обновления. Есть поиск, фильтры и имитация перезапуска. |
| **Инциденты** | Полный CRUD: создание, просмотр, изменение статуса, приоритета и ответственного, удаление с подтверждением. Есть поиск и фильтры. |
| **AI Analytics** | Аномалии по порогам и z-score. Для каждой показаны причина, уровень риска и рекомендация, из любой можно создать заявку в один клик. Ещё 3 графика. |
| **Настройки** | Тёмная или светлая тема, название кампуса, автообновление и его интервал, порог z-score. Можно сбросить тестовые данные. |

Во всех страницах есть общий sidebar и topbar. В topbar поиск помещений и устройств, колокольчик уведомлений, переключатель темы и профиль с выходом. Вёрстка адаптивная и проверена на ширине 1920, 1366, 768 и 390 px. На телефоне меню открывается кнопкой-бургером.

## AI Analytics: как это работает

Модуль не притворяется ChatGPT. Это прозрачный rule-based и статистический анализ, каждое решение можно объяснить.

1. **Пороги.** Каждый показатель сравнивается с нормой:

   | Параметр | Normal | Warning | Critical |
   |---|---|---|---|
   | Температура | 18–27 °C | 28–31 °C (или ниже 18 °C) | ≥ 32 °C |
   | CO₂ | < 1000 ppm | 1000–1499 ppm | ≥ 1500 ppm |
   | Энергия | базовая линия | +30% | +60% |

2. **Z-score.** Текущее значение сравнивается со средним μ и стандартным отклонением σ прошлых замеров (до 19 последних): `z = |x − μ| / σ`. Если `z > 2` (порог меняется в настройках), значение считается аномалией. Так ловятся резкие скачки, даже когда порог ещё не превышен. Для CO₂ и энергии учитывается только рост, для температуры — отклонение в любую сторону.

3. **Recommendation Engine.** Для каждой аномалии правило подбирает действие. Например, если людей в помещении нет, а энергопотребление высокое, система советует проверить, выключены ли компьютеры и свет.

Уровни риска:
- **Высокий** — превышен критический порог.
- **Средний** — превышен порог предупреждения или датчик offline.
- **Низкий** — аномалия найдена только по z-score.

**Имитация датчиков.** Реальных датчиков нет, поэтому `simulation.js` каждые N секунд генерирует правдоподобные показания. Они зависят от занятости помещения. Примерно в 7% замеров происходит резкий скачок, чтобы было что обнаруживать.

## Запуск

1. Откройте папку проекта в VS Code.
2. Установите расширение **Live Server**. Затем нажмите правой кнопкой на `index.html` и выберите **Open with Live Server**.
3. Войдите любым email (например `admin@campus.kg`) с паролем от 4 символов или нажмите **Демо-вход**.

Chart.js и шрифты подключаются из интернета (CDN), поэтому для графиков нужно подключение к сети. Данные хранятся в localStorage браузера. Вернуть исходные данные можно в **Настройки → Сбросить тестовые данные**.
